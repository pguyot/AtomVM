## Contract and implementation under validation

`LeafNIFFunctionType` is an explicit contract: no Erlang heap, stack or CP
changes, GC, trapping, or rescheduling. C allocation and ordinary side effects
are allowed; exceptions still use the existing MFA-aware error protocol.
The NIF structure layout and existing exported-function type values stay the
same. The emulator and generic native-call path accept the new subtype through
their existing NIF handling.

For a resolved non-tail leaf NIF with no existing heap fragments,
jit_call_ext_direct invokes the NIF and returns JIT_NATIVE_STAY directly. It
avoids the general external-call dispatcher and its arity-root setup. Existing
fragments take the general path, preserving consolidation before native
execution. Tail calls and unresolved imports also retain general handling.
Generated-code post-call reloads are unchanged. Debug assertions check heap,
stack, CP, reductions, and trap state against the contract.

Audited functions initially marked: put/2, erase/1, is_process_alive/1,
demonitor/1, and erts_debug:flat_size/1 (also registered as size_shared/1).
Demonitor/2 retains ordinary NIF handling because [flush] can trap. The current
trial additionally marks erts_internal:cmp_term/2: its comparison walker uses
C scratch memory and returns an immediate, and several compiler modules and
ordered map iterators use it.

A cached-import variant passes the already-read resolved import to the general
dispatcher on fallback, avoiding a repeated lookup. The dispatcher still uses
an acquire read of the function type, preserving concurrent native-module
upgrade publication.

## Validation in progress

The new test_leaf_nif_calls covers ordinary, tail, dynamic apply, external fun,
error/MFA-stacktrace, receive/GC, and trapping [flush] call paths. The first
fixture passes BEAM, baseline AOT, cached AOT, and an assertions-enabled JIT
build (`build.champ.assert`, Release -O3 -g without NDEBUG). ESTONE also
completes under the assertions-enabled build without a contract assertion.
The fixture uses spawn_opt/2 because the minimal C test runtime lacks the
spawn/1 wrapper. Both full Release and Debug Erlang suites pass. The final
late-heap variant also produces byte-identical output on all 280 corpus files
(`correctness.json`).

An initial fixture also exposed a pre-existing result difference for repeated
self-monitor demonitor calls followed by [flush,info]: baseline and candidate
both returned true where BEAM returned false. The call-path regression uses
[flush] and [info] separately, preserving trap coverage without changing that
unrelated behavior. This difference should be investigated separately.


## Six-function and fragment-check variants

The six-function `compare/` variant passes the full Release and Debug Erlang
suites, after replacing the fixture's unavailable spawn/1 wrapper with
spawn_opt/2. Its nine-round compiler A/B gives unicode_util 0.9941
(CI 0.9897–0.9978) and erl_parse 0.9950 (CI 0.9915–0.9988). ESTONE remains a
clear improvement: 2,489,999 → 2,544,550, ratio 1.0219 (CI 1.0188–1.0246),
BIF dispatch +27.6%, with reported runtime 745.9 → 731.8 ms (CI includes parity).

`late-heap/` moves the fragment check inside the leaf-type branch, so calls
that cannot use this path do not pay two extra dependent heap loads. In its
nine-round compiler A/B, unicode_util is 0.9983 (CI 0.9935–1.0028), and
 erl_parse 0.9978 (CI 0.9953–0.9996). This is the current candidate for final
validation. No AOT argument encoding or primitive-table ABI was changed.
